# Versioned scheduled tick runbook — bounded autonomy v1

This file is the current repository runbook for the existing half-hourly DSH driver. A reminder should contain only: **Read .loop/tick.md in C:\GitHub\DynastyWars_GA and execute exactly one scheduled tick.** Do not create another schedule, alter its timing, change profiles, start a background worker or run a nested runner.

1. Read `AGENTS.md` and run `node scripts/run-loop.mjs --preflight`. This read-only call checks global pause/writer state, review cadence, dependencies and task waits. `safety-paused` or `busy`: STOP, never recover/resume/clear a lock. `wait`: call `node scripts/run-loop.mjs --checkpoint-wait` to remember the changed fingerprint under the lock (runtime state only); no model work, repo edit, PROGRESS entry, commit or repeated options. Report only if its fresh result has `kind:wait` and `notify:true` (one consolidated notice); if readiness changed, finish this tick and let the next tick select normally. Otherwise finish quietly. Never claim a task passed merely because it is parked.
2. For ready consumer/producer work, `node scripts/run-loop.mjs --begin-manual` acquires the sole writer lock and recomputes readiness. If its JSON has `begun:false`, STOP following its wait/busy disposition—there is no report to finish. If `begun:true`, retain the exact runId/inputFile/reportPath; read inputFile and the selected spec/envelope. Do not begin twice.
3. Execute one **complete bounded work package** for the selected task, up to 25 minutes, leaving time to record/finish. Routine diagnosis, correct a proven bad measurement, local repair within already approved caps, preparation, tests, evidence and close-out are authorized under `docs/LOOP_AUTONOMY.md`; no per-command owner approval. Existing narrower owner exclusions still win. Main remains sole writer, or yields all writes to exactly one authorized foreground worker until its call settles. No background/asynchronous continuation. Current policies/caps must be read from disk, not manager-memory relays.
3-economic. In standard-econ-subagents use `docs/ECONOMIC_TAKEOVER.md`: economic-first → manager_review → one targeted linked economic correction → second quality fail → current main manager_work begin/perform/end. Keep work_id/contract/access/scope; use authoritative Host receipts, not runner hint as permission. Main rescue fits remaining tick time, no reset/new generation authority. Accepted package closes and NEXT returns economic; incomplete resumes same package within caps. Quota/owner/resource failures remain waits, not escalation. Report one advisory LOOP_WORK line with actual receipts/phase/hash before disposition/final result. In custom mode the exact preflight/wait/begin/finish calls use manager_check configured-control; unchanged waits need no economic worker.
4. If a candidate fails, reject it and proceed within the same envelope only if a concrete authorized next strategy/resources remain. Expensive request reservation must precede the image call. No cap raise, waiver, provider login, permission escalation, push/deploy or global pause reset. Default flip/legacy deletion only as the selected task's ordered slice under the owner-approved `docs/MOTION_SOLE_MODE_MIGRATION.md` (CMR-23 closed DONE by owner deferral/supersession, NOT strict-art PASS; CMR-24 still owes all practical gates and independent pre-delete review before deletion; temporary `?motion=0` rollback until the final slice; no additional image generation or mechanics changes) — never ahead of its phase gate. Preserve failed evidence. Two failed repeats of the same strategy require another evidence-backed strategy; three total failed recovery iterations park the task without resetting its counter.
5. Write the report to the exact reportPath (custom mode: manager_report with exact run_id/content after main lease end; no fake failures to grant arbitrary writes). One final standalone `LOOP_RESULT` marker. For task-local recovery/wait also use exactly one `LOOP_DISPOSITION: {JSON}` immediately above the final marker, according to `docs/LOOP_AUTONOMY.md`. Global safety/regression stays paused. Owner-wait parks the task; never labels it DONE. An ordinary partial successful package is IN_PROGRESS; a package already completed but waiting for no new input is not another attempted iteration.
6. Always call `node scripts/run-loop.mjs --finish-manual` after the report exists, including local waits or failures. Inspect returned runner result/disposition. Do not replace the runner policy with an interpretation of chat output. Missing/invalid reports and unknown active runs retain safety pause. If interrupted, preserve artifacts and report; no automated lock theft.
7. Commit locally only this package's verified changes, once (do not duplicate a consumer's commit). No waiting-only/hygiene-only commit just to show activity. Digest: task, concrete progress, checks and next authorized step. Ask the owner only for new spending, waiver, scope change, irreversible/risky operation or exhausted campaign; gather related decisions into ONE notice. No evidence change means no new question.
